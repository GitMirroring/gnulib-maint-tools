This is not needed in this case.

(CD) Create an empty disk image to be used by the virtual machine
-----------------------------------------------------------------

% qemu-img create -f qcow2 windows.qcow2 60G

60 GB is sort of a minimum. After installing a couple of Windows updates,
and after installing and using MSYS2, 50 GB of the disk are full, leaving
about 10 GB for development.

(MA) Choose the machine arguments
---------------------------------

% machine_args="-M virt -cpu neoverse-n1 -smp 4 -accel tcg,thread=multi -m 8G"
This works. Speed: violet background after 41 sec, first window after 86 sec.
or
% machine_args="-M virt -cpu max,pauth-impdef=on -smp 4 -accel tcg,thread=multi -m 8G"
This works. Speed: violet background after 43 sec, first window after 90 sec.
or
% machine_args="-M virt -cpu cortex-a72  -smp 4 -accel tcg,thread=multi -m 8G"
Does not boot from CDROM later.

For accessing USB devices (disk, CDROM, keyboard, mouse, tablet),
without getting a qemu error "-device usb-storage,drive=disk1: No 'usb-bus' bus found for device 'usb-storage'":
% machine_args="$machine_args -device qemu-xhci"

Firmware:

  - Either the UEFI firmware that comes bundled with QEMU:
    % machine_args="$machine_args -bios edk2-aarch64-code.fd"
    Provides the UEFI shell.
    "Shell>" prompt => see arm64-uefi.txt
    After command "exit", you get into the EFI's boot manager.

  - Or some UEFI firmware named 'QEMU_EFI.fd' that is part of some Linux
    distros, such as in the Ubuntu package 'qemu-efi'.
    Download https://packages.debian.org/sid/qemu-efi-aarch64 -> all -> QEMU_EFI.fd
    % machine_args="$machine_args -bios QEMU_EFI.fd"
    Provides a boot menu with, as fallback, the UEFI shell.

  - Or U-Boot.

% machine_args="$machine_args -bios edk2-aarch64-code.fd"
This works.
or
% machine_args="$machine_args -bios QEMU_EFI.fd"
This works.

Due to the choice of the 'virt' machine, it is possible to have
  - virtual USB devices (which use the guest's native USB drivers), or
  - virtual devices with virtio drivers (that have to be loaded into
    and configure in the guest OS), or
  - [maybe, I haven't tried] virtual SCSI devices.
Since the Windows 11 installer CDROM refuses to install onto an USB disk
(error message "Setup does not support configuration of or installation
to disks connected through a USB or IEEE 1394 port.", see step (IN) below),
the only working approach is *with* virtio drivers at least for the disk.
But in this situation, you can use virtio drivers also for the network
device.

(DI) Choose the disk arguments
------------------------------

There are several possibilities.

* Without virtio drivers:

  % disk_args="-drive file=windows.qcow2,format=qcow2,if=none,id=disk1 -device usb-storage,drive=disk1"
  At the QEMU level:
    (qemu) info block
    disk1: windows.qcow2
      Attached to: /machine/peripheral-anon/device[5]/scsi.0/legacy[0]
  At the UEFI level:
    PciRoot(0)/Pci(1,0)/USB(2,0).

* With virtio drivers:

  % disk_args="-drive file=windows.qcow2,format=qcow2,index=0"
  At the QEMU level:
    (qemu) info block
    virtio0: windows.qcow2
      Attached to: /machine/peripheral-anon/device[5]/virtio-backend
  At the UEFI level:
    PciRoot(0)/Pci(3,0)

  or

  % disk_args="-drive file=windows.qcow2,format=qcow2,if=virtio,id=disk1"
  At the QEMU level:
    (qemu) info block
    disk1: windows.qcow2
      Attached to: /machine/peripheral-anon/device[5]/virtio-backend
  At the UEFI level:
    PciRoot(0)/Pci(3,0)

  or

  % disk_args="-drive file=windows.qcow2,format=qcow2,if=none,id=disk1 -device virtio-blk-device,drive=disk1"
  At the QEMU level:
    (qemu) info block
    disk1: windows.qcow2
      Attached to: /machine/peripheral-anon/device[5]
  At the UEFI level:
    VenHw(...)

(NW) Choose the network arguments
---------------------------------

There are several possibilities.

* Without virtio drivers:

  % net_args="-netdev type=user,id=net0 -device e1000,netdev=net0,mac=52:54:00:12:34:56"

  This provides an ethernet interface:
  (qemu) info network
  e1000.0: index=0,type=nic,model=e1000,macaddr=52:54:00:12:34:56
   \ net0: index=0,type=user,net=10.0.2.0,restrict=off

* With virtio drivers:

  % net_args=""

  This provides an ethernet interface by default:
  (qemu) info network
  hub 0
   \ hub0port1: #net160: index=0,type=user,net=10.0.2.0,restrict=off
   \ hub0port0: virtio-net-pci.0: index=0,type=nic,model=virtio-net-pci,macaddr=52:54:00:12:34:56

  % net_args="-nic user,model=virtio-net-pci"

  This provides an ethernet interface too:
  (qemu) info network
  virtio-net-pci.0: index=0,type=nic,model=virtio-net-pci,macaddr=52:54:00:12:34:56
   \ #net068: index=0,type=user,net=10.0.2.0,restrict=off

(DV) Choose the display/video arguments
---------------------------------------

% display_args="-device ramfb -device usb-kbd -device usb-tablet"
This works.
or
% display_args="-device VGA -device usb-kbd -device usb-tablet"
Not useful: The display does not get initialized.
or
% display_args="-nographic"
This option is useful only for experimenting with the UEFI shell.

(B1) Boot from the disk
-----------------------

% common_args="$machine_args $disk_args $net_args $display_args"

In order for the UEFI to recognize the CDROM, we need to attach it via USB.

* Without virtio drivers:

  % qemu-system-aarch64 $common_args \
      -drive file=windows11-installer.iso,format=raw,media=cdrom,if=none,id=installer -device usb-storage,drive=installer

* With virtio drivers:

  % qemu-system-aarch64 $common_args \
      -drive file=windows11-installer.iso,format=raw,media=cdrom,if=none,id=installer -device usb-storage,drive=installer \
      -drive file=virtio-win.iso,format=raw,media=cdrom,if=none,id=virtio-drivers -device usb-storage,drive=virtio-drivers

When the prompt "Press any key to boot from CD or DVD..." appears, press any key.
You should soon see a rotating Windows cursor.
